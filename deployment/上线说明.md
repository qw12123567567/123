# 云端常驻部署

该部署让服务独立于本机运行。服务账号由你持有，费用由你确认后开通；当前尚未创建云端服务或公网网址。

## 已准备的配置

- `render.yaml`：Render新加坡区常驻服务、10GB持久化磁盘、健康检查、正式管理员初始化。
- `deployment/Dockerfile`：Node 24独立镜像，应用以非root用户运行。
- 默认演示账号不会进入新正式数据库；正式模式禁用演示动态码。
- Cookie使用Secure标记，TLS由平台终止。
- 台账、说明书和备份均位于持久化目录，重启不会清空。

## 发布流程

1. 用你自己的账号登录Render，并绑定支付方式。不要选择会休眠的免费计算实例。
2. 把项目源码上传至你自己的私有Git仓库。不要上传`data/`、日志或密钥。
3. 在Render创建Blueprint，选择私有仓库，读取`render.yaml`。
4. 用`node deployment/generate-secrets.mjs`在本机生成初始密码和认证器密钥，将两者填入平台对应密钥项。将动态验证密钥导入自己的认证器，勿提交至仓库。
5. 核对服务、磁盘及带宽费用，确认后部署。部署成功后平台分配`https://...onrender.com`固定网址。
6. 设置`APP_URL`为实际公网网址；如需邮件找回与邮件提醒，再配置`RESEND_API_KEY`、`MAIL_FROM`及有效发信域名。未配置邮件渠道时，管理员仍可重置账号密码，站内提醒可用。
7. 在手机蜂窝网络验证登录、新增、上传、下载、价格权限；执行一次备份及恢复校验，再导入正式台账。

## 数据迁移

生产初始化拒绝已知演示密码，不能直接把含演示账号的本机数据库暴露公网。优先在正式空环境中建立部门、角色和账号，再从本机导出设备导入正式环境；附件迁移需要逐设备带权限导入。确认实际数据量后再执行迁移。

## 恢复

系统每日生成SQLite一致性备份并对数据库和私有附件执行AES-256-GCM加密。系统设置可做隔离恢复校验；请单独安全保管`DATA_DIR/.backup-key`，或配置64位十六进制`BACKUP_ENCRYPTION_KEY`。完整恢复命令：

```text
node deployment/restore.mjs device-ledger-YYYY-MM-DDTHH-MM-SS-sssZ.sqlite.enc /var/restored-ledger
```

恢复到新目录，核对设备及附件后，停止旧实例并将`DATA_DIR`切换至新目录，避免覆盖在线数据库。

数据库和附件的同盘备份只能防误操作，云端正式投产仍需另加异地副本。单实例维护或重新部署会有短暂不可用，不承诺零中断。
